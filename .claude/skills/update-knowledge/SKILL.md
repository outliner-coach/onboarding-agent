# 지식 문서 갱신

이 레포의 지식 문서는 `plugins/onboarding-agent/skills/guide/knowledge/`에 있다. 설치된 플러그인은 이 폴더의 사본을 읽으므로, 여기서 고치고 `main`에 병합해야 사용자에게 반영된다.

대상: $ARGUMENTS (비어 있으면 `last_checked`가 가장 오래된 가이드부터 3개)

## 필요한 것

Notion과 Slack 커넥터가 연결돼 있어야 한다. 없으면 갱신할 수 없으니 그 사실을 알리고 멈춘다. 기억으로 내용을 채우지 않는다.

## 기존 가이드 갱신

1. 가이드 frontmatter의 `sources`에 있는 원문을 다시 읽는다.
2. 가이드 내용과 원문을 비교한다. 달라진 절차, 링크, 수치, 담당 셀을 찾는다.
3. `#_qna_genie`(C4UHULRPB)에서 해당 주제의 최근 스레드를 검색한다. 문서에 없는 막힘 지점이나 문서와 다른 실제 관행이 있는지 본다.
4. 가이드를 고친다. 원문끼리 다르면 한쪽을 고르지 말고 `gaps.md`의 상충 표에 적는다. 다만 `gaps.md`의 "확인이 끝난 것"에 있는 항목은 담당 셀이 답을 준 것이다. 원문에 낡은 값이 남아 있어도 확인된 값을 유지한다.
5. `last_checked`를 오늘 날짜로 바꾸고, `index.md`의 기준일과 상태를 맞춘다.
6. "확인이 필요한 것" 중 이번에 해소된 항목은 지운다.

## 새 가이드 추가

1. `gaps.md`의 "아직 가이드로 만들지 않은 주제"나 최근 `#_qna_genie` 질문에서 주제를 고른다.
2. Notion에서 원문을 찾는다. 검색 결과 중 아래 "제외할 문서"에 해당하는 것은 쓰지 않는다.
3. 기존 가이드와 같은 구조로 쓴다: frontmatter, 한 줄 요약, (갈림길이 있으면) 먼저 물어볼 것, 절차, 자주 막히는 곳, 문의, 확인이 필요한 것.
4. `index.md`에 행을 추가한다. "이런 질문에" 칸에는 사람들이 실제로 쓰는 표현을 넣는다.
5. 새로 확인한 flex 양식은 `workflows.md`에, 담당 셀과 채널은 `contacts.md`에 넣는다.

## 서비스 공식 문서

`official-docs.md`는 Google, Slack, Notion 같은 외부 서비스의 공식 도움말 링크를 모은 파일이다. 사내 가이드는 "누구에게, 어디에 신청하나"를, 공식 문서는 "그 서비스 화면에서 어떻게 하나"를 맡는다.

- 가이드를 갱신하거나 새로 만들 때, 제품 조작이 들어가는 단계가 있으면 해당 서비스의 공식 도움말에서 문서를 찾아 링크한다. 조작법을 사내 문서에서 옮겨 적는 대신 공식 문서를 가리킨다.
- 공식 도움말 도메인에서만 찾는다(예: support.google.com, slack.com/help, notion.com/help, support.atlassian.com, guide.flex.team). 블로그와 커뮤니티 글은 넣지 않는다.
- 기존 링크는 열어서 살아 있는지, 내용이 가이드의 설명과 여전히 맞는지 확인한다.
- 공식 문서와 사내 절차가 다르면 사내 절차를 따르되, 차이를 가이드의 "확인이 필요한 것"이나 `gaps.md`에 적는다. 사내 문서끼리 다를 때 공식 문서가 한쪽을 뒷받침하면 그 사실을 적는다.

## 상태 값

- `문서확인`: 이번에 원문을 직접 읽고 절차를 확인했다.
- `부분확인`: 일부만 확인했다. 빈 부분을 "확인이 필요한 것"에 적는다.
- `미확인`: 전사 표준 문서가 없다.

직접 읽지 않은 원문을 근거로 `문서확인`을 붙이지 않는다.

## 레포에 넣지 않는 것

원문에는 평문 비밀이 섞여 있다. 아래는 옮기지 않고 "Notion 원문에 있다"고만 적는다.

- 비밀번호(와이파이 포함), 공용 계정 아이디와 비밀번호
- 계좌번호, 카드 정보
- 내부 IP와 내부 전용 호스트 주소
- 개인 이름, 개인 전화번호, 개인 이메일. 담당자는 셀과 채널로 적는다.
- 특정 구성원의 휴가, 급여, 건강에 관한 사례

커밋 전에 변경분에서 위 항목을 검색해 확인한다.

## 제외할 문서

같은 키워드로 검색되지만 현행이 아닌 것들이다.

- "근로감독 대응" 폴더의 공지 사본
- Archive, Archieved, Deprecated 폴더
- "Confluence Migration", "워크스페이스 샘플"
- 제목에 "(구버전)", "(과거 사용방식)", "사본"이 붙은 문서

## 마무리

변경 내용을 브랜치에 커밋하고 PR을 연다. PR 설명에는 무엇이 바뀌었는지, 어떤 원문을 읽었는지, 담당 셀 확인이 필요한 항목이 무엇인지 적는다.
