# 사내 와이파이 세팅

## 한 줄 요약

업무용 와이파이 `BPK_IAP`에 연결한 뒤, NAC 인증 포털에서 요구하는 설치와 인증 네 가지(백신, NAC Agent, 장비 인증, 구글 계정 인증)를 마쳐야 인터넷이 된다. 설치 파일을 받으려면 중간에 게스트망 `BPK_GAP`로 바꿔야 할 수 있다. 사용자 인증은 **매달 1일에 초기화**되므로 매달 다시 해야 한다.

## 망 종류

| SSID | 용도 | 조건 |
| --- | --- | --- |
| `BPK_IAP` | 업무용 인터넷망 | 아래 설치·인증 필요 |
| `BPK_TAP` | 모바일 테스트망(스테이지 접속) | 모바일 기기만. 목록에 보이지 않는 히든 방식 |
| `BPK_GAP` | 게스트용 | 신청 없이 인터넷만 사용. 사내 시스템(어드민, Redash, NAS 등)은 접근 불가 |

비밀번호는 여기에 적지 않는다. [Notion 원문](https://app.notion.com/p/ee9db86c1ec34bdf9f592c9ebaacb3f4)의 OS별 연결 방법에 있다.

## 미리 알아 둘 것

새 노트북은 아래 네 가지를 모두 마쳐야 `BPK_IAP`에서 인터넷이 된다. 와이파이 암호만 넣으면 끝나는 일이 아니다.

| 필요한 것 | 어디서 |
| --- | --- |
| 백신(Bitdefender) 설치 | 설치 파일을 내려받아 설치 |
| NAC Agent 설치 | 인증 포털의 agent 페이지 |
| 장비(MAC 주소) 인증 | 인증 포털의 `nacpass` |
| 회사 구글 계정 인증 | 인증 포털의 `인증` 버튼 |

- **`BPK_IAP`는 네 가지를 마치기 전에는 인터넷이 안 된다.** 그래서 설치 파일을 받아야 하는데 받을 수 없는 상황이 생긴다. 이럴 때는 게스트망 `BPK_GAP`로 잠시 바꿔서 내려받고 설치한 뒤 `BPK_IAP`로 돌아온다.
- 반대로 인증 포털과 agent 페이지는 `BPK_IAP`에 연결된 상태에서만 열린다. 두 와이파이를 오가게 된다.
- 백신이 설치된 상태로 지급되는 경우도 있지만, 새 맥북은 직접 설치해야 했던 사례가 있다. 포털이 백신이 없다고 하면 아래 3번을 따른다.
- 휴대전화를 옆에 두면 편하다. 노트북 인터넷이 끊긴 동안 Notion 원문을 휴대전화로 볼 수 있다.

## 절차 (`BPK_IAP`)

1. **와이파이 연결**
   - Windows: 화면 오른쪽 아래 Wi-Fi 아이콘 → `>` 버튼 → `BPK_IAP` → 연결 → 암호 입력
   - macOS: 화면 오른쪽 위 Wi-Fi 아이콘 → 다른 네트워크 → `BPK_IAP` → 암호 입력. 붙여넣기가 실패하면 직접 입력한다.
2. **(macOS 15 이상) 무작위 MAC 주소 끄기**: 시스템 설정 → Wi-Fi → `BPK_IAP` 옆의 세부사항 → 비공개 Wi-Fi 주소를 `끔`으로 바꾼다. 이 네트워크에만 적용된다. 공식 문서: [Mac에서 비공개 Wi-Fi 주소 사용하기](https://support.apple.com/guide/mac-help/use-a-private-wi-fi-address-on-mac-mchlb1cb3eb4/mac). 사내 문서: [무작위 MAC 주소 해제 가이드](https://app.notion.com/p/31f1f5a7134480bf91d5c56ab6249799).
3. **NAC 인증 포털에서 상태 확인**: 처음 연결하면 인터넷이 안 되거나 특정 페이지로만 이동한다. 정상이다. 포털이 네 가지 중 무엇이 빠졌는지 알려 준다. 포털 주소는 Notion 원문의 "OS 공통" 항목에 있다.
4. **백신(Bitdefender) 설치** — 포털이 백신이 없다고 할 때
   1. 설치 파일 링크는 Notion 원문의 "사무실 인터넷망 SSID가 궁금해요" 항목에 Windows용과 Mac용이 있다.
   2. `BPK_IAP`에서 내려받기가 안 되면 와이파이를 `BPK_GAP`로 바꿔서 받는다.
   3. macOS: 받은 `.dmg` 파일을 열면 디스크 이미지가 열리기만 하고 설치되지는 않는다. **열린 창 안에 있는 설치 파일을 한 번 더 실행해야** 설치가 시작된다.
   4. 설치 프로그램이 본체를 추가로 내려받는다. 설치가 끝날 때까지 `BPK_GAP` 연결을 유지한다.
   5. macOS가 시스템 확장 허용이나 전체 디스크 접근 권한을 요청하면 허용한다. Bitdefender 공식 문서 기준으로는 설치 후 시스템 설정의 개인정보 보호 및 보안에서 직접 허용해야 하는 항목이다: [보안 에이전트 설치 절차](https://www.bitdefender.com/business/support/en/77212-157497-install-security-agents---standard-procedure.html), [전체 디스크 접근 허용](https://www.bitdefender.com/business/support/en/77209-157543-allow-full-disk-access-to-bitdefender-endpoint-security-for-mac-in-macos-mojave--10-14-.html).
   6. 설치가 끝나면 와이파이를 다시 `BPK_IAP`로 바꾼다.
5. **NAC Agent 설치** — 포털이 agent가 없다고 할 때: `BPK_IAP`에 연결된 상태에서 포털의 agent 페이지를 열고 OS에 맞는 agent를 받아 설치한다.
6. **장비(MAC 주소) 인증** — 포털 화면의 MAC 값에 취소선이 있을 때: `nacpass` 버튼으로 MAC 인증 페이지를 열어 그 값을 입력한다. 아래 "등록되지 않은 장비라고 나올 때" 참고.
7. **구글 계정 인증**: 포털의 `인증` 버튼을 눌러 회사 구글 계정으로 인증한다.
8. **확인**: 포털에 남은 항목이 없고 일반 웹사이트가 열리면 끝이다. 아직 막혀 있으면 포털을 다시 열어 남은 항목을 본다.
9. **매달 1일 이후 구글 계정 재인증**: 알림봇이 매월 1일 `#_qna_genie`에 공지한다.

MAC 주소 확인
- macOS: 애플 메뉴 → 이 Mac에 관하여 → 시스템 리포트 → 네트워크
- Windows: 명령 프롬프트에서 `ipconfig /all` → 어댑터별 물리적 주소

## 이 컴퓨터에서 직접 확인할 수 있는 것 (macOS)

에이전트가 사용자의 맥에서 실행 중이면, 묻기 전에 아래 읽기 전용 명령으로 상태를 확인할 수 있다. 설정을 바꾸는 명령은 사용자에게 먼저 묻는다.

```bash
sw_vers -productVersion                                  # macOS 버전. 15 이상이면 비공개 Wi-Fi 주소를 꺼야 한다
networksetup -getmacaddress Wi-Fi                        # 장비 고유의 Wi-Fi MAC 주소
ifconfig en0 | grep ether                                # 지금 쓰고 있는 MAC 주소
ls /Applications | grep -i -E "bitdefender|endpoint"     # 백신 설치 여부
```

- 고유 MAC과 지금 쓰는 MAC이 다르면 비공개 Wi-Fi 주소가 켜져 있을 가능성이 높다.
- Wi-Fi 장치 이름이 `en0`이 아닐 수 있다. `networksetup -listallhardwareports`로 확인한다.
- NAC Agent가 설치돼 있는지는 프로그램 이름을 확인하지 못해 명령으로 판별하지 못한다. 포털 화면으로 확인한다.

## 등록되지 않은 장비라고 나올 때 (새 노트북, 신규 입사자 맥북)

새로 받은 노트북을 `BPK_IAP`에 처음 연결하면 인터넷이 차단되고, 인증 포털에 `MAC=xx:xx:xx:xx:xx:xx` 값이 **취소선**으로 표시된다. 그 장비의 MAC 주소가 아직 허용 목록에 없다는 뜻이다. 고장이 아니고, 본인이 직접 등록할 수 있다.

1. 포털 화면에 취소선으로 표시된 MAC 값을 그대로 복사한다.
2. 포털의 `nacpass` 버튼을 눌러 MAC 인증 페이지를 연다. 주소는 Notion 원문의 "OS 공통" 항목에도 있다.
3. 복사한 MAC 값을 입력해 인증한다.
4. 포털로 돌아가 `인증` 버튼으로 회사 구글 계정 인증을 마친다.

인증했는데도 계속 차단될 때
- **macOS 15 이상**: 비공개 Wi-Fi 주소가 켜져 있으면 인증한 MAC과 실제로 쓰는 MAC이 달라진다. 위 절차 2번대로 끄고, 포털에 표시되는 값으로 다시 인증한다.
- 입력한 MAC 값에 오타가 없는지 확인한다. 포털에 표시된 값과 한 글자도 다르면 안 된다.
- Windows에서 유선과 무선을 함께 쓰면 라우팅 문제로 차단된 것처럼 보일 수 있다. DevOps셀이 안내하는 라우팅 재설정 스크립트를 실행한다.
- 그래도 안 되면 `#_qna_genie`에 포털 화면 캡처를 올린다. DevOps셀 담당이 자리로 와서 봐 주기도 한다.

함께 알아 둘 것
- 휴대전화와 태블릿은 `BPK_IAP`가 아니라 `BPK_GAP`를 쓴다.
- 회사가 지급하지 않은 개인 노트북을 사내에 들여와 쓰려면 결재 서식 `정보 자산 반입/반출 신청서`가 필요하다. [accounts-and-access.md](accounts-and-access.md) 참고.
- 테스트용 단말기를 업무망에 연결하려면 결재 서식 `테스트 단말기 업무망 연결 신청/삭제`를 올린다.

## 자주 막히는 곳

- `BPK_IAP`에서 설치 파일이 내려받아지지 않는다 → `BPK_GAP`로 바꿔서 받고, 설치가 끝나면 `BPK_IAP`로 돌아온다.
- 백신 `.dmg`를 열었는데 설치가 안 된다 → 열린 창 안의 설치 파일을 한 번 더 실행한다.
- 포털에서 인증서 경고가 뜬다 → 고급(advanced)을 눌러 계속 진행한다.
- 포털 새로고침이 안 된다 → 탭을 닫고 다시 연다.
- G-Suite 인증이 안 된다 → Safari 대신 Chrome으로 시도하고, 안 되면 재부팅한다.
- MAC 인증 후에도 안 된다 → 입력한 MAC 주소 오타를 확인한다.

## 그래도 안 되면

`#_qna_genie`에 증상을 올리고 DevOps셀 네트워크 담당을 찾는다. 올릴 내용: OS와 버전, 어느 단계에서 막혔는지, 포털에 표시된 메시지.

## 확인이 필요한 것

- 백신과 NAC Agent 중 무엇을 어느 와이파이에서 받아야 하는지, 설치 순서가 정해져 있는지는 실제 사례 한 건에 근거한다. DevOps셀 확인이 필요하다.
- 백신 설치 후 macOS 권한 허용이 사내 배포본에서도 필요한지는 Bitdefender 공식 문서 기준이고 사내에서 확인하지 못했다.
- 디스크 이미지 안의 설치 파일 이름, NAC Agent의 프로그램 이름은 확인하지 못했다.
- Notion 문서 본문은 `BPK_IAP`, QnA는 `BPK_IAP_20F`로 SSID 표기가 다르다. 목록에 보이는 이름으로 연결한다.
- 인증 포털이 등록되지 않은 장비에 대해 정확히 어떤 문구를 보여 주는지는 확인하지 못했다. 채널 사례는 모두 "MAC 값에 취소선"으로 설명한다.
- 유선 어댑터나 독을 쓰면 MAC 주소가 달라 따로 인증해야 하는지는 확인하지 못했다.
- `BPK_TAP` 사용 신청은 예전 flex 전자결재 절차가 취소선 처리돼 있고 대체 절차가 없다. 모바일 외 기기 연결은 DevOps셀에 문의한다.
